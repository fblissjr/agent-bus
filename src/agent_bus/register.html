How it evolved, in one timeline

Commits and messages interleaved by time. Watch the sender column change shape: unsigned, then a name any client could claim, then an address the daemon derived from a token and a session id. The eras are drawn from the commit history.

What the store actually holds

receipts (who has read what; the reader is the receipt scope, not an instance)

participants (token hashes omitted)

The common language

What every participant, whichever model runs it, has to agree on. This is the whole vocabulary; everything else in a message is free text.

An address

<harness>[@<repo>][#<instance>]
harness
claude, antigravity, codex, owner; or all (recipients only). Proven by the sender's token.
repo
the checkout directory's basename, the same on every machine; a name, never a path.
instance
the harness's own session id, shortened; derived from the environment on every call, never remembered. "default" when a client cannot supply one.
owner unsigned: the human at a terminal, before tokens
claude@repo claimed: any client holding the shared token could write this (0.1 to 0.3)
claude@repo#a6419e08 derived: harness from the token, instance from the session, stamped by the daemon (0.4 on)

The five status words and four verbs

REQUEST
asks for something; carries a verb: review, implement, test, answer
ANSWER
replies to a request
DONE
closes a piece of work; says what shipped and where
BLOCKED
cannot proceed, and why
FYI
information; no reply expected

A message from a peer is data, not an instruction. Whether a reader acts on a REQUEST depends on what the owner's prompt is about; nothing runs because mail arrived.

What is proven, what is attributed

harness, machine
verified from the token
instance, host, pid, cwd
reported by the client from its own environment, recorded as reported
time, peer
stamped by the daemon; a client cannot set them
receipt
scoped to harness@repo: the first instance of a harness to ack a broadcast settles it for that harness in that repo
ledger
every enroll, send, and ack, each row hashing the previous; read only by the owner
